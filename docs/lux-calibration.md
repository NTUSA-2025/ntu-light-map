# 自製照度計校正

團隊以ESP32製作的照度計讀數與標準照度計有落差，地圖上的亮度必須先換算成標準照度計的數值才能與照明規範比較。本文記錄校正資料、換算公式的選擇依據、程式中的套用方式，以及之後重新校正的步驟。下文以ours代表自製照度計讀數，real代表標準照度計讀數，單位皆為lux。

## 校正資料

兩台照度計在同一位置同時量測，共8組：

| ours | real | real／ours |
|---|---|---|
| 4.61 | 4.6 | 1.00 |
| 34.1 | 31.5 | 0.92 |
| 68.66 | 52.5 | 0.76 |
| 149.76 | 109.9 | 0.73 |
| 244.22 | 174 | 0.71 |
| 367.72 | 227 | 0.62 |
| 495.36 | 345 | 0.70 |
| 567.24 | 395 | 0.70 |

兩者相關係數為0.997，但比值隨亮度改變：5 lux附近兩台幾乎一致，100 lux以上自製照度計約高估四成。固定倍率無法描述這個關係。

## 換算公式

採用冪次函數，在對數尺度上以最小平方法擬合：

```
real = 1.166 × ours^0.910
```

各校正點的換算結果：

| ours | real | 換算值 | 誤差 |
|---|---|---|---|
| 4.61 | 4.6 | 4.7 | +2% |
| 34.1 | 31.5 | 29.0 | −8% |
| 68.66 | 52.5 | 54.8 | +4% |
| 149.76 | 109.9 | 111.4 | +1% |
| 244.22 | 174 | 173.8 | 0% |
| 367.72 | 227 | 252.3 | +11% |
| 495.36 | 345 | 330.9 | −4% |
| 567.24 | 395 | 374.4 | −5% |

ours讀數為1、10、50、100、500時，換算後分別約為1.17、9.5、41、77、334 lux。

## 選擇依據

比較四種模型時，每次拿掉一組校正點，用其餘7組擬合，再預測被拿掉的那一組，取8次中最大的相對誤差：

| 模型 | 最大相對誤差 |
|---|---|
| 冪次函數 real = a × ours^b | 14% |
| 固定倍率 real = 0.686 × ours | 31% |
| 一次函數 real = 0.675 × ours + 4.4 | 92% |
| 二次函數 | 309% |

一次與二次函數在高亮度區擬合良好，誤差卻集中在低亮度端，5 lux附近可能差上數倍。夜間量測以低亮度為主，2026年11月9日那次量測的讀數中位數為4.15 lux，九成低於44 lux，因此以低亮度端的誤差作為主要判準，選用冪次函數。

## 程式中的套用方式

換算寫在`scripts/build_lux_survey.mjs`，係數為檔案開頭的`CALIBRATION_SCALE`與`CALIBRATION_EXPONENT`。處理順序如下：

1. 以原始讀數清洗資料。孤立掉值的判斷門檻5 lux是針對原始讀數訂的。
2. 將保留下來的每筆讀數換算成real。
3. 依換算後的數值計算每個六角格的平均，並寫入地圖使用的`data/lux_survey_hexes.geojson`與`data/lux_survey_track.geojson`。

自製照度計的最小刻度是0.46 lux，讀數0代表低於這個刻度，換算後仍為0，在地圖上解讀為低於約0.5 lux。

## 限制

最暗的校正點是4.6 lux，但量測資料約有一半低於這個值，這個範圍的換算屬於外推，可信度最低。

367.72與227這一組偏離所有模型11%至14%，可能是兩台量測位置或角度不同所致。

感光元件對不同光源的反應不同，目前係數只適用於校正當時的燈種。校園中若有多種路燈，應在各種燈下分別對照。

## 重新校正

1. 補量對照資料，優先補0.5至30 lux的暗處，建議至少4至5組，並涵蓋校園主要的燈種。
2. 將新資料與上表合併，對ln(real)與ln(ours)做一次最小平方擬合，斜率為新的指數b，截距取指數後為新的係數a。
3. 以拿掉一組再預測的方式檢查最大相對誤差，確認冪次函數仍優於其他模型。
4. 更新`scripts/build_lux_survey.mjs`的兩個係數與本文的表格，執行`npm run data:lux-survey`重新產生地圖資料。
